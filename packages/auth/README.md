# @bolt/auth

First-party password authentication, SQL-backed opaque sessions, and explicit resource authorization. Runtime dependencies are other Bolt packages only. Password hashing uses Bun's Argon2id implementation through `@bolt/security`.

Create `SqlSessionStore(database)` and run its `migration()` through `SqlMigrator`. Supply a `UserProvider` that resolves password credentials by login and returns only active users from `findById`. `SessionAuth.login(context, login, password)` verifies credentials and issues a new session, replacing the request's previous session. `require(context)` returns the current active user or throws HTTP 401. `middleware()` protects route groups; `Gate.authorize(user, resource, policy)` throws HTTP 403 unless the application policy returns `true`.

Session user IDs must be nonempty strings of at most 255 UTF-16 code units. SQL Server and Oracle use Unicode columns. Session expiry is an integer Unix timestamp in milliseconds; invalid records are rejected before writes. Custom table names are limited to 30 ASCII identifier characters; migration index names incorporate a digest of the complete table name, so tables with the same long prefix can coexist.

Cookies default to `__Host-bolt_session`, `Secure`, `HttpOnly`, `SameSite=Strict`, and path `/`, with no domain. Use `secure: false` only for local HTTP development; that defaults to `bolt_session`. Session tokens have 256 random bits; only SHA-256 digests enter the SQL ledger. The default absolute lifetime is eight hours. Rotation atomically revokes the previous token, preserves absolute expiry, and allows one concurrent winner. Logout and `store.revokeUser(id)` revoke sessions. Run `store.purge(Date.now())` periodically to remove expired records.

Passwords, tokens, and cookies must never enter logs. Configure CSRF protection for cookie-authenticated mutations (including login), rate limiting for credential endpoints, TLS at the deployment boundary, and application-owned tenant/resource policies. Permissions are resolved from the user provider on every request. Already running requests are not canceled by later revocation. This package does not implement MFA, password reset, OAuth/OIDC, or account provisioning. Unknown accounts perform a dummy Argon2 verification; this is not a guarantee of indistinguishable timing across database/provider implementations.

There is no sliding or idle timeout: rotation preserves the absolute lifetime. Provider outages and SQL failures propagate as errors and do not authorize a request. Replacement/rotation failures before COMMIT roll back the previous session deletion. If `SqlPostCommitError` reports `committed: true`, the new session was persisted but no cookie is issued: reauthenticate rather than assuming rollback or replaying the transaction; expiry/purge removes the unreachable token. Authentication cookies are issued only after successful transaction cleanup. `login` returns the provider's current user for application use: explicitly select public fields before serializing it, and apply `Cache-Control: no-store` to authentication and private responses.

`examples/persistence` demonstrates optional protected routes, login/logout/rotation, CSRF, and read/write permissions. The SQL store supports the same dialects and transport contracts as `@bolt/database`.
