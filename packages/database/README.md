# @bolt/database

`Database` retains the original synchronous SQLite API. `SqlDatabase` provides async executors for SQLite, PostgreSQL, MySQL, MariaDB, SQL Server and Oracle. SQLite uses `bun:sqlite`; PostgreSQL/MySQL/MariaDB use Bun SQL pools. SQL Server/Oracle require an explicit first-party `@bolt/database-odbc` transport and native system drivers.

`SqlDatabase.create(options)` has an explicit `start()`/`close()` lifecycle. `execute(sql, parameters)` binds values separately from SQL; identifiers remain application-owned. `transaction(async executor => ...)` pins one connection, supports nested savepoints, and rolls back on callback failure. Use the callback executor, never the root database inside its session. Executors cannot escape their callback lifetime. Named databases are registered explicitly in `SqlConnections`.

`SqlMigrator` runs an explicitly supplied migration catalog in ID order, with SHA-256 checksums and cross-process locks. Modified/missing applied migrations and dirty records block execution. `sqlMigration(id, statements)` derives its checksum from immutable SQL content. MySQL/MariaDB/Oracle DDL can commit implicitly and requires `{ transactional: false }`; failed migrations can leave partial schema and a dirty record requiring reconciliation. Oracle's default session lock requires output bindings and `EXECUTE` on `SYS.DBMS_LOCK`; an application can provide its own deployment-specific `lock`.

**Transaction outcome matters:** `SqlPostCommitError` with `committed: true` means COMMIT was acknowledged but later session cleanup failed. Never compensate persisted work or automatically replay that transaction. Errors before acknowledgement do not prove rollback if the connection was lost during COMMIT; the database may have accepted it. Resolve uncertain outcomes using application idempotency keys/readback. Callback and cleanup failures are preserved together through `AggregateError`. Raw SQL/autocommit commands are not classified by `SqlPostCommitError`; use explicit transactions for write workflows that require this outcome contract.

Pools have bounded connection counts; shutdown drains outstanding sessions, so application callbacks must finish. Native Bun SQL query cancellation/deadlines are not exposed by this minimal executor contract. Configure server statement timeouts and application deadlines for long-running SQL; an abandoned promise is not query cancellation. The ODBC transport additionally bounds operations, queues and response sizes. No failed transaction is automatically replayed.

Tests cover real SQLite and opt-in native servers via `BOLT_POSTGRESQL_TEST_URL`, `BOLT_MYSQL_TEST_URL`, and `BOLT_MARIADB_TEST_URL`; ODBC tests document their separate configuration. `bun scripts/verify-recovery.ts` creates isolated Docker servers and verifies interrupted transactions, durable rollback, pool reconnection and subsequent writes. This is a bounded failure test, not a sustained-load benchmark.
